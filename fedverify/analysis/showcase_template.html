    What it protects

    Covered, and not covered

    The full threat model, with every case spelled out, is in THREAT_MODEL.md next to the code.

    ✓Covered

    • A hospital cannot change, replay or re-spend an update after signing it.
    • Nobody can submit as a hospital without that hospital's registered key.
    • The server cannot misreport which updates entered a round: each round root is anchored and every hospital can check its inclusion proof.
    • Updates with NaN, infinite or extreme values are rejected before aggregation.
    • One poisoned hospital is screened with a threshold calibrated from data, never set by hand.
    • The logistic model's training examples are protected by differential privacy.

    ✕Not covered

    • Adaptive attackers, and more than one colluding hospital.
    • A server that computes the average wrongly: aggregation is not proven.
    • Privacy of the tree models: random forest and XGBoost have no differential privacy.
    • Stolen keys, multi-factor authentication and firewalls (not simulated).
    • Forks of the chain, several aggregators, and dropped submissions.
    • A real network: the chain runs as one local node.

    Reproduce

    Three commands rebuild everything on this page

    python3 -m fedverify.survival.experiments all --jobs 4

    Runs every experiment: methods, privacy sweep, chain runs, calibration, ledger attacks and poisoning.

    python3 -m fedverify.analysis.make_fl_healthcare_all

    Rebuilds every table, figure and the results draft from the results files.

    python3 -m fedverify.analysis.make_showcase

    Rebuilds this page from the same results files.
